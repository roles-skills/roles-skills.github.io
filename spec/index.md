# Website: specification

This file covers only the website. The monorepo's data, validation, and writing rules are in [`../CONTRIBUTING.md`](../../CONTRIBUTING.md), and publishing is in [`../spec/monorepo-github-pages/`](../../spec/monorepo-github-pages/).

## Purpose

Publish the digital health care job roles reference as a static website at <https://roles-skills.github.io>, so that anyone can find a role level, read it, assess themselves against it, and link to it, without cloning anything.

## Constraints

- **Static.** Every page is prerendered to HTML at build time. There is no server, no database, and no runtime API. GitHub Pages serves `build/` as files.
- **Self-contained.** The project builds from its own directory. It reads nothing outside itself at build time, so it still builds after being pushed to its own repository. Its inputs are vendored by `bin/sync`.
- **Generic.** The content describes a generic digital health care organisation. The theme picker offers only Lily's generic themes, not national government or public-sector themes.
- **Accessible.** Semantic HTML, one `h1` per page, visible focus, a skip link, breadcrumbs, and no colour-only signalling. Every self-assessment control is a labelled radio button or textarea inside a `fieldset` with a legend naming its skill.

## Stack

| Piece | Choice |
| --- | --- |
| Framework | SvelteKit 3, Svelte 5 runes |
| Adapter | `@sveltejs/adapter-static` |
| Design | [Lily Design System™](https://lilydesignsystem.com/) headless components and `PickerBar` |
| Content editing | [Sveltia CMS](https://github.com/sveltia/sveltia-cms) at `/admin/`, editing the monorepo's `data/` |
| Package manager | pnpm |
| Hosting | GitHub Pages, deployed by GitHub Actions |

## Vendored inputs

Refreshed by `bin/sync`. Never edit them by hand.

| Path | Source |
| --- | --- |
| `content/reference.json` | the monorepo's `exports/reference.json`, generated by `scripts/build.py` |
| `static/downloads/` | the monorepo's `exports/` TSV files and `reference.json` |
| `static/assets/themes/` | Lily's generic reference themes, per `bin/lily-themes.txt` |
| `static/admin/config.yml` | generated by the monorepo's `scripts/cms_config.py` |

## URLs

Trailing slashes always. The directory is the slug.

| Path | Page | Count |
| --- | --- | ---: |
| `/` | Home | 1 |
| `/roles/` | Role finder, searchable, filterable by band | 1 |
| `/roles/<role>/` | A role: summary, levels, health context, PCF description, ESCO occupations and their skills | 73 |
| `/roles/<role>/<level>/` | A role level: responsibilities, skills, band outline, job evaluation, self assessment | 292 |
| `/families/` and `/families/<family>/` | Role families | 1 + 15 |
| `/bands/` and `/bands/<band>/` | Bands, outlines, and the role levels in each | 1 + 12 |
| `/skills/` and `/skills/<skill>/` | Skills, their four levels, ESCO links, and the role levels that expect them | 1 + 253 |
| `/job-evaluation/` | The 16 factors, levels, points, and band ranges | 1 |
| `/about/` | Provenance, frameworks, downloads, licence | 1 |
| `/admin/` | Sveltia CMS (static file, not prerendered) | 1 |
| `/sitemap.xml` | Every prerendered page | 1 |

Links to documents in the monorepo on GitHub use the document's directory, for example `https://github.com/roles-skills/roles-skills/blob/main/docs/roles/product-manager/`.

## Self assessment

Each role level page has a self assessment, in `src/lib/SelfAssessment.svelte`. For each skill, the reader picks a rating from Not yet (0) to Expert (4), sees the gap against the expected level, and writes evidence, plus a development action where there is a gap. Answers are saved to `localStorage` under `roles-skills:self-assessment:<path>` and restored on the next visit. The reader can export them as TSV in the monorepo's self-assessment columns, which `scripts/gap_analysis.py` reads, or download the blank TSV. Nothing is sent anywhere.

## Site tools

Every page carries `PickerBar` from `@lilydesignsystem/svelte-picker-bar` in the header: theme, language, text size, and share pickers. The theme defaults to `corporate`, a calm blue, and is stored under `roles-skills:theme`. The text size is stored under `roles-skills:text-size`. Every route hydrates, because the toolbar and the self assessment need JavaScript.

## Page layout

Single column, with no sidebars. Every page has breadcrumbs, and one `h1` in a `.page-intro` block. That class is deliberately not `.hero`, because Lily's theme stylesheets style `.hero` as a coloured banner.
